## 3. Распределение ответственности между модулями
*   `data.js` — хранит исходные наборы данных (`demoTasks`, `variantTasks`).
*   `task-service.js` — чистая бизнес-логика (создание, поиск, обновление статуса, удаление, статистика).
*   `task-selectors.js` — фильтрация задач (выборка для отображения).
*   `task-view.js` — создание DOM-элементов карточек, обновление сводки и пустого состояния.
*   `main.js` — управление состоянием (текущий массив, фильтр), обработка событий и вызов отрисовки.

## 7. Отладка
Для отладки использовалась панель DevTools (вкладка Sources -> Event Listener Breakpoints -> Mouse -> click). 
Была установлена точка останова в `main.js` в функции `handleTaskListClick`. 
При нажатии на кнопку статуса было зафиксировано:
1. `event.target` — это `span.action-label`.
2. `button` (через `closest`) — это `button[data-action="toggle"]`.
3. `id` (из `dataset.taskId`) — строка `"23"`, после `Number()` — число `23`.
4. Результат работы `setTaskCompleted` — объект `{ok: true, tasks: [...]}` с обновленным массивом.
Это подтвердило, что событие проходит путь от вложенного элемента до вызова сервиса корректно.
